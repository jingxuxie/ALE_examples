# Execution and isolation

Each concept's `participant/` is the complete allowed task export. Do not expose the parent directory to a tested agent. Evaluators, hidden inputs, private generators, planted designs, source snapshots, other attempts, and generation logs are privileged.

System requirements: Linux x86-64, Python 3.10 or newer, libseccomp and Landlock for concept 1's execution isolation; Python standard library suffices for the supplied baselines and mathematical validators. A C/C++ compiler and NumPy/SciPy are available to fresh sessions as system tools, but are not required by the baselines. No pip install or mutable upstream compiler dependency is needed.

Run the first tournament with `python3 authoring/run_tournament.py N` from the package root. This invokes the user's unmodified `run_allowlisted_codex.sh` with model `ultima-alpha`, effort `xhigh`, ephemeral sessions, no approvals, no web, read-only participant access, an initially empty writable `attempts/v_1/`, and a 3,600-second wall-clock limit. Invocation logs and metadata live beside the output directory, not inside its allowlist. Filesystem hashes attest that task assets were not changed. No generation agent is used as a fresh participant.

The first concept 1 launcher invocation was stopped before agent initialization because it inherited an open stdin pipe. Its infrastructure-only log and metadata are preserved as `attempts/infrastructure_stdin.*`. The launcher now supplies `/dev/null` on stdin. Concept 3 also has an aborted preflight-only initialization preserved as `attempts/infrastructure_preflight.*` and `infrastructure_preflight_output/`: two read-only-workspace prose issues were corrected before its clean fresh launch. Neither initialization produced scientific work or counts as a scored attempt; their logs contain only the stdin initialization line.

Evaluate an executable routing submission with `python3 concept_1/evaluator/evaluate.py concept_1/attempts/v_1 --output concept_1/attempts/v_1.score.json`. Its process runs from a writable copied submission, with an empty temporary scratch directory, system runtime paths, and the current instance on stdin. This preserves the ordinary relative-file behavior of `python3 solve.py`; neither the original submission nor hidden files are writable or readable outside the allowlist. Landlock blocks private filesystem reads; seccomp blocks networking and cross-process inspection; CPU affinity, address-space, CPU/wall time, file-size, and descriptor limits bound resources. Isolation probes are preserved in `concept_1/evaluator/hidden/validation.json`. Working-directory compatibility was audited without changing inputs, objectives, or resource targets. An additional canonical evaluation of the immutable first routing submission is saved as `concept_1/attempts/v_1.score.canonical.json`; the initial score is retained separately rather than silently replaced.

Concepts 2 and 3 evaluate static witnesses without executing participant code. Run each `evaluator/evaluate.py --help` for its accepted path argument. Their validators parse bounded JSON, replay every gate with exact integers, and recompute all claimed resources. No participant-provided validity, cost, or equivalence assertion is trusted.

`authoring/concepts.md` records the eight-concept pre-tournament shortlist; only three concepts are built. `authoring/sources.md` records provenance. Each `status.json` and retained score artifact records the empirical classification; an unknown passing solution is never upgraded to demonstrated achievability.

Concept 3 also receives a second independent fresh trial on the identical frozen generation-1 task. Its output index is `attempts/v_2`; this is a replication, not a ratchet or a task change. Neither trial can read the other. Both must fail the complete witness condition to retain this version as empirically hard.

For later routing and falsification generations, pass their nested `participant/` to `run_tournament.py --participant` and the matching nested evaluator to `collect_attempt.py --evaluator`. Original versions and score artifacts remain immutable. Concept 1 generation 2 declares a 12-second per-case and 360-second suite limit before its launch, rather than treating noisy startup-time outliers under generation 1's tighter limits as evidence of scientific hardness.

Run `python3 authoring/audit_package.py --require-complete --output authoring/final_audit.json` after all trials are graded. This checks launch metadata, unchanged participant exports, frozen submission hashes, required score fields, and construction-instance commitments. Mathematical replay, negative-case validation, and adversarial-search evidence remain in the individual concept directories.
