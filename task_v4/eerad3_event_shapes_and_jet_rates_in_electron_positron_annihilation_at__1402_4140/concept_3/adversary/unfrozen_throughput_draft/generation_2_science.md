# Generation-two scientific and numerical audit

## Active revision: unique B4 resident-array production batches

### Final resource boundary

The active implementation compiles the immutable batch wrapper and the three
submitted sources into a PIC shared library. A trusted parent creates fresh
resident shared input/output buffers and forks, without loading that library.
Trusted child code touches all shared pages, records its own user/system CPU,
sends those values on a private pipe, and closes the pipe before CDLL loading.
The parent subtracts only that immutable pre-candidate setup record from kernel
RUSAGE_CHILDREN measured after reaping the child and all adopted descendants.
Library constructors, loading, numerical work, output stores, and descendants
remain included. No candidate code exists at the earlier timing boundary, so
native timer-symbol interposition cannot alter the excluded setup record.
This explicitly supersedes the earlier full-startup metrics below. Native,
full-child, and trusted-setup CPU are all retained for audit; no denominator
floor, repeated input, or candidate-reported timing is introduced.

The constructor probe checks both its process identity and at least 0.14 CPU
seconds charged for 0.15 CPU seconds of library initialization. An early-exit
probe must fail physics despite valid prepopulated output headers. The original
physical corpus and every numerical gate remain unchanged through all transport
revisions. The public helper implements the same resident-buffer library ABI.

The earlier 1,724-case, 18x repeated-work proposal below is **superseded**,
not a freeze candidate. It is archived in `generation_2_repeated_proposal`.
Repeating identical calls permits memoization; writable run mounts permit
cross-trial caches. The active revision instead preserves that entire
1,724-event prefix and adds 8,280 independently drawn events, all validated
by the same three oracle constructions. There are 10,004 distinct momentum
inputs, 18 families, and 1,100 events in each of the nine light strata.
No numerical tolerance or orientation allowance changes.

Each native process maps resident binary arrays, executes every event exactly once,
and returns every 84-component record. There is no warmup, replay loop, or
TIME/checksum trailer. Every record from every timing trial is checked against
its reference and physical gates. Compilation is writable; native execution
mounts compiled /work read-only and receives fresh /tmp, /dev, and IPC/PID/
network namespaces. No writable cache survives into another process.

The predeclared resource policy is the minimum of 8 and 0.45 times the smaller
of two independently measured generation-one incumbent median paired CPU
ratios, rounded downward to 0.001. It requires
at least a measured twofold throughput improvement on this unique-event
production batch. The old repetition-based 18x allowance is not carried over
blindly; the private adaptive witness does not determine the threshold.
The final value is in `evaluator/hidden/target.json`; measurements are in
`unique_calibration_*.json` and `unique_repeat_*.json`. Each campaign compiles
again, launches new processes, and checks every numerical record; the repeat
does not reuse candidate output. The fixed threshold and public contract precede
every generation-two fresh attempt. `generation_2_unique_preparation.json`
commits the active package without creating a generation freeze.

The small-record binary prototype is separately preserved in
`unique_small_record_draft`. Reading an array of derived event records caused
many small transfers and produced noisy baseline CPU times of 0.043–0.152
seconds and incumbent ratios of 1.31–5.46. Those numbers are **not hardness
evidence**, and the implied 0.903x target was never committed. The active
protocol instead stores four contiguous buffers: momenta(4,5,N), labels(5,N),
slots(3,N), and axes(4,N), read in four bulk operations. Output was already
bulk records(84,N). The supervisor exposes child user/system CPU separately
to distinguish native arithmetic from system/I/O costs.

The bulk-read/pipe-input draft is preserved in `bulk_pipe_draft`. It improved
incumbent user CPU to a stable 0.168–0.180 seconds, but system-time variability
left total paired ratios of 3.03–6.89 (median 4.684). No target was committed
from that draft. The subsequent sealed-input but allocating-native draft is
preserved in `allocating_memfd_draft`. Its incumbent median was 2.903x, with
pairs spanning 1.55–8.59x; baseline native allocation/zeroing/copying still
incurred about 2,360 minor faults and substantial variable system CPU.
That draft also committed no resource target and supplies no hardness claim.

The active B4 protocol has a 16-byte aligned header (eight-byte magic,
uint32 count, zero uint32 reserved word) followed by the same four SOA buffers.
The native driver maps sealed input and shared output with populated pointer
views. The trusted supervisor physically fills output pages with the header
and zero records before spawning any native process. Thus no submitted code
or candidate precomputation occurs during staging. The complete child lifetime,
including startup, mmap, page-table work, array access, output stores, arithmetic,
and adopted descendants, remains charged by user-plus-system CPU. There is no
candidate-controlled phase timer. Small event-local copies preserve the original
mutable Fortran argument behavior. This represents a native caller supplying
resident arrays, not repeated transport allocation around the scientific kernel.
An early-exit native control must have its prefilled all-zero output rejected
by physical/numerical gates despite its syntactically valid B4 header.

Before either sealed-input campaign, the policy was revised to require two
independent incumbent medians within a factor of 1.30 and paired-ratio relative
median absolute deviations at most 25% in both incumbent and private-control
campaigns. A private control must pass all numerical gates and remain below
80% of the independently incumbent-determined limit in both campaigns.
Per-run max/min CPU spreads are reported, not hidden. The claim is repeatable
median throughput separation, never a favorable single trial or a near-budget
failure. Neither private-control performance nor user-only CPU sets the limit.
The evaluator, binary protocol, corpus, and total-CPU metric remain unchanged
between these campaigns. The coordinator measures first and commits only in
a separate explicit finalization step. No generation is frozen or launched.

The trusted in-namespace subreaper remains the CPU authority. Binary bulk
I/O replaces ASCII formatting; no artificial denominator floor or repeat
amplification is used. Five pairs alternate order on the same pinned CPU.
Active controls verify adopted-child CPU, read-only /work and supervisor,
fresh tmpfs across processes, linked timer interposition, malformed/trailing

## Domain, not an observable-selection claim

The public contract is a massless five-particle CM **mapping-kernel** domain,
with arbitrary valid radiator choices and no jet-resolution or event-shape
cut. Construct four positive-energy null vectors, choose the fifth spatial
vector as minus their spatial sum, and take its positive spatial norm as
its energy. Common normalization/rescaling and input/output permutations
preserve this domain up to the stated binary64 rounding. Nearly collimated
four-particle antennae therefore form valid test inputs, even when a separate
three-jet analysis would reject the complete event.

The 1,620 new events are a stratified numerical production stress workload,
not unweighted physical Monte Carlo events and not a claimed cross-section
frequency. All nine 180-event strata are retained, with no failure-based
filtering. They combine balanced, hierarchical, soft-radiator, doubly-soft
radiator, soft-unresolved, and nested openings, then continue to somewhat
wider light clusters. Internal angles reach 1e-12; radiator chords stay
above 1e-10 in the new data. Energies and overall scales stay within the
already published domain. The original 104 cases and their references
are preserved as an exact list prefix, including their limit identities
and linked metamorphic checks.

Primary literature inspected: Gehrmann-De Ridder et al., EERAD3,
arXiv:1402.4140, especially Sections 3.2–3.4; Kosower, *Multiple Singular
Emission in Gauge Theories*, arXiv:hep-ph/0212097, Section 6,
Phys. Rev. D 67, 116003, DOI 10.1103/PhysRevD.67.116003; and

The exact local DAK2 weights and branch were also checked against the

## Independent derivation of the oracle

Let C = a + u + v + b be the antenna sum, and define the original weights
r1 = (s_ub + s_uv)/(s_au + s_ub + s_uv),
r2 = s_vb/(s_av + s_vb + s_uv). For U = r1*u + r2*v the required map is
A = U + x*a + y*b, B = C - A, with the spectator untouched.
The two shells A² = B² = 0 imply C·A = C²/2. Eliminating y produces
an affine line whose direction is a - (C·a)/(C·b)*b. Its intersection
with A² = 0 gives the existing geometric quadratic; the positive
radiator-directed solution reproduces the DAK2 branch. Conservation and
both shells alone do not specify a map, so matching these weights and
this branch is essential.

The new independent implementation does not reuse that quadratic or its
discriminant polynomial. It constructs pair invariants from
s_ij = E_i E_j |n_i - n_j|², boosts the antenna to its rest frame, and
intersects the affine spatial line with a Euclidean sphere of radius
sqrt(C²)/2. It removes the line-parallel component to find the sphere
center projection, chooses the positive radiator-directed intersection,
and boosts back. This rest-frame sphere calculation is structurally
different from both the covariant quadratic and expanded DAK algebra.

All methods use the exact received binary64 spatial coordinates with
E = |p|, not unavailable pre-rounding generator values. For every final
case, validation compares geometric calculations at 140/190 digits,
direct DAK at 160 digits, and rest-frame sphere construction at 180 digits.
Input CM/null residuals, output positive energies, and output null shells
are separately checked. `evaluator/hidden/oracle_validation.json` reports
the actual maxima. Zero reported reference disagreement means agreement
after conversion to binary64, not a proof of exact analytic equality.

No quality tolerance was tightened. `oracle.py` is byte-identical to its
generation-one snapshot, including the near-parallel orientation allowance
16*epsilon_binary64/d and its doubled mapped-invariant allowance.

## Genuine demotion failure

The initial 180 light events expose the real generation-one champion's
unconditional wide fallback cost (29.989x under the old timing method),
but a global real16-to-real10 fallback demotion passes them. A further
1,080 tighter/hierarchical events also fails to break that demotion.
Continuing the same physical construction toward broader, still light
clusters with two soft radiators does break it. The full 1,620-event
search, not a selected subset, is used in generation two.

Two private examples in `conditioned_transition_scores.json`:

| Case | C²/Q² | radiator chord | max component error/Q | allowed component error/Q |
| --- | ---: | ---: | ---: | ---: |
| light_transition_double_soft-0052 | 3.7519692504e-7 | 4.1893389227e-10 | 9.6629472771e-6 | about 8.48e-6 |
| light_transition_double_soft-0174 | 6.3242294465e-7 | 3.0914232839e-10 | 3.3264193020e-5 | about 1.15e-5 |

Both also fail mapped-invariant comparison. Their minimum energy fractions
are 6.7674e-13 and 1.1018e-9, respectively; neither is an exact singularity
or out-of-domain radiator opening. All independent references agree.
The unchanged generation-one champion passes the 1,620 numerical probes.

The demoted expanded DAK discriminant subtracts large nearly equal Gram
terms and divides by a squared small radiator invariant. This can lose
meaningful digits when radiator softness and angular hierarchies combine.
The private `adaptive_wide` control estimates propagation of this Gram
roundoff and retains the wider fallback when that estimate is large;
it is not a case lookup. Its final quality/cost claims must be taken from
the trusted generation-two evaluation, not from this rationale.

## Fixed target and trustworthy resource measurement

The recommended target is every one of 1,724 cases and every one of 18
families, with the unchanged numerical gates and unchanged 18x CPU budget.
There is no threshold fit to a new fresh solver. The target, public
distribution, source hashes, and measurements protocol are committed in
`generation_2_preparation.json` before any generation-two attempt. Main
must review and perform the actual generation freeze; this preparation
does not create `frozen_generation_2.json` or launch an agent.

The supervisor is a separate read-only file inside the bubblewrap PID
namespace. It enables child-subreaper accounting, waits for adopted
descendants, and reads kernel RUSAGE_CHILDREN after completion. Its own
CPU and compilation are excluded; all native startup, I/O, and kernel
execution are included. A zero-forged libgfortran CPU_TIME symbol cannot
lower this cost. Bounded native logs are returned only after all child
processes have exited; the supervisor disables dumpability to protect
its process and file descriptors. Five adjacent pairs alternate order
on one pinned CPU. Baseline-only repeat calibration makes each baseline
sample at least 0.5 CPU seconds without adding a fictitious cost floor.

The resource control suite checks timer interposition, an orphaned child
that burns 0.15 CPU seconds after its parent exits, and a write attempt
against the mounted supervisor. Generation-one files and measurements
remain auditable under the original 40-file hash seal in the snapshot.
