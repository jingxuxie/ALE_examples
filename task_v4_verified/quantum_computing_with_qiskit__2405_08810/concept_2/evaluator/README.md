# Privileged evaluator and handoff

This directory is private. Release only `../participant/` to a fresh solver,
along with a new, empty output directory. In particular, never expose `hidden/`,
`../adversary/`, status/build reports, other attempts or champions. Directory
names alone do not provide isolation; the parent orchestrator must enforce an
allowlist that prevents traversal to the concept root.

## Grading interface

From the concept root, on an immutable submission snapshot:

```bash
python -I -B evaluator/evaluate.py /path/to/output/solution.json --output /path/to/score.json
python -I -B evaluator/evaluate.py --submission /path/to/output
```

`--solution` is another spelling of `--submission`. The positional argument may
also name a directory containing `solution.json`. Every ordinary result is a JSON
object on stdout; optional `--output` writes the same report. Exit codes are zero
for full acceptance, one for an invalid/incorrect/over-budget submission, and two
for evaluator infrastructure/integrity failure. No submitted code is imported or
executed. There is no reference-circuit comparison or execution-based grading.

The evaluator loads only its own `_checker.py` and `hidden/instances.json`,
checks their SHA-256 hashes against `frozen.json`, and uses strict bounded JSON
parsing for the witness. It never imports the participant checker or reads
participant matrices during grading. `-I` protects against attempt-controlled
Python import paths. The public checker is a byte-identical transparency copy at
release; only its copy's command-line default input path is participant-relative.

## Feasibility and validation

`hidden/generate_instances.py` is the private generator. Its cryptographic seed,
selection indices, planted gate programs and schedules live only in `hidden/`.
Normal grading does not read or require any of them. The public matrices were
generated by native programs with 146, 178, 214 and 246 CX gates. Graphs have
degrees two and three; bottleneck cases join two chorded patches with two links.
Random disjoint-edge batches with randomized orientations prevent directly
cancellable gates across commuting intervening gates. The private selection
filter requires all hardware edges to occur, row/column weights at least two,
and matrix density at least 28 percent. It does not select on a solver's failures.

Count caps are `ceil(1.06 * planted_count)` and weighted-depth caps are
`ceil(1.08 * planted_depth)`. They have already been materialized in the immutable
instance JSON. The evaluator never derives or adjusts caps from a submitted
artifact. The generator refuses to overwrite an existing generation.

```bash
python -I -B evaluator/hidden/generate_instances.py --verify
python -I -B evaluator/selftests.py --report adversary/selftests.json
python -I -B evaluator/audit_build.py --report adversary/build_audit.json
```

`selftests.py` tests exact semantics independently using dense NumPy matrix
products and a NetworkX dependency DAG, baseline routing, private witness
feasibility, caps at equality and one beyond, altered matrices and witnesses,
all-or-nothing acceptance, strict parsing, file-type defenses, evaluator asset
pinning and independence from public files. `audit_build.py` records immutable
release hashes and scores without updating thresholds. Its report is private.

The stored routed Gaussian baseline is an author-run baseline, not a fresh-agent
attempt or a champion. Feasibility is established; empirical fresh-agent hardness
is deliberately **untested**. The parent controller owns fresh-agent testing and
the eventual hardness classification. Do not describe this build as
`hard_verified_achievable` before those attempts occur.
