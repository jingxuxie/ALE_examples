# Anti-compression and isolation audit

The two assessed subcomponents are significant-support recovery (`recovery_score`, F1) and probability estimation (`estimation_score`, calibrated uncapped L1 plus spectral loss). Neither can be replaced by fitting the dominant identity. The total rational score is strictly decreasing in positive uncapped loss; no numerical-error cap or clipped grading interval is used. The raw reference loss is independently required below 0.1 in addition to the calibrated score exceeding 0.9 on every case, so normalization cannot conceal a poor reference.

Distinct families: collision-limited supports; several-hundred to several-thousand-fold probability range; physical approximately sparse channels with thousands of subthreshold errors carrying 4% of nonidentity mass. The challenge pool increases hash occupancy and measurement noise and increases dynamic range in its corresponding family. These stay in the same calibrated-eigenvalue observation model and retain commuting hashes; there is no arbitrary adversarial corruption or unsupported physical assumption. Seed plus region changes support, matrices, offsets, noise, and dimensions without searching for seeds the reference happens to solve.

Why not one universal dense kernel: at 40 qubits a single float64 probability vector needs `8*4**40 = 9.67e24` bytes; at 100 it needs `1.29e61` bytes. Even an idealized trillion Walsh additions per second requires millions of years already at 40 qubits. `benchmark.json` computes exact storage counts and explicit optimistic time estimates; no hazardous allocation is attempted. A low-weight NNLS fit is executable as `weak_solver.py`, using identity plus all weight-one Paulis. It has a tractable design but cannot represent these high-weight events. Conditional NNLS is useful only after resolving the unknown support; it does not solve collision detection or sign decoding.

`benchmark.py --ablations` additionally measures a single discovery pass and peeling without joint probability refinement. Each discovery pass admits every validated new candidate up to the output capacity. Raw losses, F1, matched-support probability errors, and runtime are retained; no unsupported empirical hardness claim is made. A fresh-agent attempt is deliberately absent and left to the main author's runner.

Public surface: `participant/TASK.md`, `participant/input/FORMAT.md`, one unlabeled `example.npz`, and an empty workspace. Inputs contain only the seven documented observation/schema arrays. No seeds, family names, planted labels, reference outputs, decoder, or source discussion are public. `max_terms` is a capacity, not the actual support count.

The parent opens output with `O_NOFOLLOW` and validates/loads the same regular-file descriptor; a solver cannot point its output at a private cached answer. Solver logs are read through the parent's retained descriptor, not by reopening a child-controlled pathname. These checks close parent-side symlink reads that filesystem confinement of the child alone would not prevent.

Every strong-reference and weak-baseline calibration run uses the common Landlock wrapper. The only granted task directory is the temporary staged directory, NOT the original reference/submission parent. This distinction prevents a reference run from gaining access to its adjacent truth files. The child receives a clean environment, one-thread BLAS, writable HOME/TMPDIR/cache, isolated Python startup, 2 GiB address space, CPU and wall limits, a 32 MiB individual-file limit, and 64 open descriptors. Input files and code are copied; output validation and truth scoring occur only in the parent. Pool manifests and solver logs are not passed to the solver. Common wrapper availability is required; failure does not silently fall back to unsandboxed execution.
