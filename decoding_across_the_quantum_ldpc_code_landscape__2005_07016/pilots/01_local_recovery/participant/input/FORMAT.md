# Interface

The input NPZ contains `h_rows`, `h_cols` (zero-based nonzero coordinates, no duplicates), `h_shape` (checks, variables), `priors` (independent fault probabilities, one per variable), and `syndromes` (shots by checks, binary). Optional scalar `budget_seconds` reports the batch runtime allowance. All parity arithmetic is over GF(2). The output NPZ must contain binary `corrections` with shape (shots, variables).

For every row, `H @ corrections[row] mod 2` should equal its syndrome. A valid correction still fails if it changes the encoded logical information: evaluation tests `L @ (correction xor actual_fault) == 0` using the code's hidden logical operators. Equivalent stabilizer representatives are accepted; matching a particular reference vector is not required. Faults are sampled independently with the supplied, possibly nonuniform, priors. Code families include hypergraph products, high-rate sparse-code fixtures, and repeated surface-code extraction detector models. Matrices and indices may be permuted.

Core quality is the fraction of shots satisfying both conditions, normalized so the weak decoder scores 0 and the strong decoder scores 1, without clipping above 1. Runtime multiplies this by `(1 + reference_seconds / budget_seconds) / (1 + submitted_seconds / budget_seconds)`. Times and budgets are single-core CPU seconds including compilation and startup; wall time and peak resident memory are also reported. Exceeding the CPU budget, invalid output, or exceeding a wall allowance of `max(60, 3 * budget_seconds)` scores 0. Mean and worst-family scores are both reported. A zero normalization gap is reported as an uninformative case rather than used to manufacture hardness. Numerical libraries and compilers are available, but specialized quantum decoder packages are not.
