# Authoring checks and exclusions

- The source paper's appended material is part of its 15-page version (Appendices A–C). No separate unpublished supplement is claimed.
- All later solver packages are installed under this output directory's `research/vendor`, not into the participant runtime. Original 2020 native source is preserved as an actual pre-solution artifact, including its upstream license.
- Initial random regular HGP sampling admitted repeated classical columns, hence accidental distance-two constituents. Calibration exposed poor reference logical recovery. Such constituents are now excluded before sampling errors; dimensions remain unchanged. This is pre-pilot scientific validation, not an agent-guided threshold ratchet.
- The official `lx_400_16_6.npz` stores 128 explicit zero entries alongside 128 ones. A first serialization audit reconstructed these as ones. Explicit zeros are now removed, all scored reference cases regenerated, and evaluator accuracies must match generation manifests exactly before any score is emitted. The faulty authoring result is not counted as an agent failure.
- System numerical libraries inside the evaluation container are NumPy 1.21.5 and SciPy 1.8.0. The private reference environment is pinned to NumPy 1.26.4, SciPy 1.13.1, ldpc 2.4.1, and Stim 1.16.0. Specialized private packages are not mounted into submitted processes.
- A public smoke test inside the evaluation container succeeded. Its 12.90-second wall time versus 0.53 CPU seconds exposed significant host/mount startup jitter. Algorithm performance is therefore measured using process user plus system CPU time, with a separate generous wall safety allowance. Runtime, memory, and raw correctness remain separately visible.
- The evaluator mounts only the supplied participant tree, submitted tree, one sanitized input, an empty result directory, and standard OS files. Original participant/submission absolute paths are preserved as aliases in addition to `/task` and `/submission`, avoiding false failures caused by deployment-path remapping. Private reference and challenge directories are never mounted. Network and process namespaces are isolated.
- The global BP+OSD_CS8 baseline consumed at least 588 seconds at 99.9% CPU without finishing its 12-shot HGP stage, whereas official BP+LSD_CS8 decoded the complete 192-shot batch in 3.93 CPU seconds. This is evidence against that measured global configuration, not a claim that every optimized OSD-0 approach has already been ruled out.
- Startup-only aborted CLI invocations are documented separately in `runs/INFRASTRUCTURE.md`; they are excluded from solver scores. The final report must identify all completed scored invocations and preserve their logs, requested model, budget, and artifact hashes.
